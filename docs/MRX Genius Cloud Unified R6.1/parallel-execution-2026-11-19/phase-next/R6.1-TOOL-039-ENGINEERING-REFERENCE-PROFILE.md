## B. Mathematical Integrity

### B.1 Fixed reference limits and equations

Engine constants (standard adult ULN):

| Marker | ULN | Unit |
|---|---:|---|
| ALT | 56 | U/L |
| AST | 40 | U/L |
| GGT | 60 | U/L |
| ALP | 147 | U/L |
| Bilirubin | 1.2 | mg/dL |

For each valid, date-sorted series per marker:

- `uln_multiple = round((latest_value / ULN[marker]) * 100) / 100`
- Status thresholds: `>= 5` → `critical`; `>= 3` → `high`; `> 1` → `elevated`; otherwise `normal`.
- Trend when at least two valid readings exist: `trend_per_30d = round(((latest - first) / max(1, days)) * 30 * 100) / 100`, where `days` is the elapsed-day difference between the first and latest supplied dates.
- Marker rows are sorted by descending `uln_multiple`.
- Overall status is the highest rank among marker statuses (`normal < elevated < high < critical`).
- Cholestatic escalation: if bilirubin `uln_multiple > 1.5` and overall is `elevated` or `high`, overall is escalated one rank and a seek-evaluation recommendation is added.
- `stop_orals` is true only for `high` or `critical` overall.
- Additional fixed recommendations cover mild elevation on orals, alcohol `> 7` drinks/week, absent TUDCA with oral use or non-normal status, no valid readings, and normal results.

### B.2 Input guards and degenerate values

- Zod bounds: marker enum `ALT|AST|GGT|ALP|bilirubin`; value finite `0..5000`; unit string `1..24`; date ISO-parsable; `1..100` readings; alcohol integer `0..100`; booleans required.
- The engine independently skips non-finite values and unparsable dates. It does not coerce empty strings to zero; the UI validates empty input as missing before a payload exists.
- Typed `0` is a valid value and is carried end-to-end.
- If no valid readings remain, the result has an empty marker list, overall `normal`, `stop_orals: false`, and a “No valid readings” recommendation. This is an engine outcome, not a clinical normal finding.
- No unit conversion is performed; the entered unit is passed through and the contract explicitly requires the same unit on both sides of cross-tool mappings.
- Determinism is structural: same parsed input plus same caller-injected options produce the same engine result and the same envelope. The UI freezes `calculatedAt` once per mount for stable envelopes.

### B.3 Verification boundary

Three engine tests, eight pipeline tests, twenty-five contract tests, and thirty-eight component tests are declared in the working tree. Their names cover normal/high/cholestatic cases, schema rejection, envelope guard, determinism, no conversion, typed zero, debounce, stale gating, ordered boxes, and local-only persistence. **None was executed in this audit** (`NOT_RUN`); therefore those declarations remain static E2 observations here, not newly awarded E3.

The EN/AR capability contract states that the tool can compute status, ULN multiples, and 30-day trend from entered readings, and that it **cannot diagnose, cannot prescribe or stop medication, cannot predict future values, and does not use any AI model, image recognition, voice input or lab-report reader**. ## D. User Experience

### D.1 State model

`components/tools/tool-039-liver-enzyme-tracker.tsx` derives:

| State | Trigger | Pipeline behavior |
|---|---|---|
| `EMPTY` | No readings | Never called |
| `PARTIAL` | Missing required value/date/alcohol or unanswered tri-state field | Never called |
| `INVALID` | Non-numeric, negative, out-of-range, or impossible date | Never called |
| `FULL` | Complete valid input and matching signature | Result rendered |
| `DEGRADED` | Complete input whose pipeline returns an error | Error reason shown |

Empty is never coerced to `0`; typed `0` remains valid. `Yes / No / Unanswered` remain distinct. Deleting all readings returns the UI to `EMPTY`. A `DEGRADED` result is shown only for the current `inputSignature`.

### D.2 Interaction and presentation

- 120 ms debounce suppresses one calculation per keystroke during edit bursts.
- `inputSignature` prevents stale pipeline output from being presented as current.
- Lab freshness uses a 90-day rule on the newest draw date; stale data is flagged, not presented as current.
- EN/AR strings and LTR/RTL direction are driven by global display preferences. Historic 390px/1440px and AR/RTL screenshots exist, but they are pinned to historic deployments and are **not** current-HEAD E4 evidence.
- Result boxes are hidden while input is incomplete, and the history box remains visible with an explicit reason rather than being silently hidden.
- CSV export is a client-side Blob download. The separate P-04 print-summary component is unadopted.
- A local “Load sample readings” control exists in the source; this corresponds to P-05 synthetic demo data and remains unadopted/owner-gated (see §F.3).

### D.3 Local storage boundary

History is implemented through `lib/tools/r6/tool-039-liver-enzyme-tracker-history-store.ts` as `local-device` storage under D-08 Option A, with storage keys `mrx_tool039_history_v1` and `mrx_tool039_history_key_v1`.
