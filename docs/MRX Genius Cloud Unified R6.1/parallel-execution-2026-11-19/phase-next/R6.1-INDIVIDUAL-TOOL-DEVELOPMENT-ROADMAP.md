## 1. What this plan is and is not

- It converts the already-verified per-tool gap registers (Section M) and Section P task proposals into an honest, gate-aware sequence. It adds no new evidence and awards no E3/E4/E5 level.
- Only E3+ counts as PASS. E2 stays E2. `NOT_AVAILABLE` is not `NOT_APPLICABLE`. A recorded PASS is not re-awarded at HEAD `37f047a4`.
- No tool is at 100% VERIFIED and no tool is owner-accepted. Tool 039's historic `OWNER_ACCEPTED` status belongs to 039 alone and is not transferable.
- Denominators differ: the 18-row grid is operational only for the 19 tools with no richer authoritative source; 040 uses 92 applicable rows (123-row CSV), 041 uses 132 (138-row CSV), 042 uses 53 atomic rows, and 045–051 use 26–72 atomic rows. Percentages below are quoted on the tool's own basis and are never compared as if they shared a denominator.
- "Local" means tool-local code, test, or evidence work under an already-completed per-tool audit. "Gated" means external owner/specialist/browser decision or shared P-03 approval. Local work can never close a gated row.

## 3. Sequencing by gate-complete feasibility (not by percentage)

**Selection rule (explicit).** The first development tool is one whose genuine remaining gaps are LOCAL (tool-local code, test, or evidence) with the **minimum un-gated unresolved rows**, requiring **no shared-component edit** and **no owner-decision freeze**. High recorded percentage alone never qualifies a tool: a tool whose remaining rows are all external gates cannot advance locally.

- **WAVE A — first local, minimum un-gated rows (4 of 7 local rows), no freeze, no shared edit.** **`008` is the selected first development tool** (3/18 recorded PASS, 4 un-gated rows, fully tracked clean artifacts, first task `tool-008-i18n-check.mjs` re-run/archive with acceptance exit 0 and 105/105). `014` is the co-equal alternate (also 3/18, 4 un-gated rows; constraint: never fabricate `NO_VALIDATED_MODEL`). Both are PRESERVE: their local work is evidence integrity, not new capability.
- **WAVE B — local work available (5–7 un-gated rows), no freeze, no shared edit.** `006`, `015`, `025`, `026`, `027`, `029`, `031`, `034`, `037`, `038`, `043`, `044`. These have real tool-local tasks (i18n scripts, test tracking, focused re-runs, header/purity fixes). Their duplicate-box concerns are E4-gated diagnostics only — do not touch `R6ToolShell.tsx`, `boxes.ts`, `manifest.ts`, `registry.ts`, or the route page.
- **WAVE C — local work with an owner-decision prerequisite.** `016`, `022` (canonical route/name conflicts), `017` (real input schema needs owner/source decision), `023` (CRITICAL clinical dose output needs D-CLIN/D-C4), `035` (live-pipeline wiring needs owner confirmation; W18 POST needs ruling). Local tasks may be prepared but the owner decision must be recorded before the affected change.
- **WAVE D — substantial E2-to-E3 local test uplift, tool-owned boxes.** `050` (9 static rows), `051` (8 static rows + 2 FAIL/E0 + WT i18n fix). Their recorded percentages are deliberately corrected downward; the work is genuine, but it must not be presented as recovering the old PASS count.
- **WAVE E — local-looking work that is actually shared-approval or durability bound.** `046`, `048`, `049` (single runtime-negative row each, but the file is the shared, approval-gated P-03 suite); `040` (83.70% recorded rests on an untracked artifact set — local commit + re-run plus 15 browser rows). These require P-03 / scoped-commit authorization before local work counts.
- **WAVE F — external-gates-only, no local work available.** `045`, `047` (no engineering gap; only 5 browser + 4 owner gates). They can be prepared for the gate but cannot be advanced by this workstream.
- **FROZEN / NOT SCHEDULED.** `041` = OWNER_REVIEW — NOT ACCEPTED — NOT CLOSED (owner freeze; no implementation task until lifted; preserve superseded v1-123 set). `042` = STOPPED — ORDER 580 (change-control register only; no restart, activation, or development task, and no unilateral registry change).

Special-case note: `040`, `045`, and `047` have high recorded completion but are gate/durability-bound; they are not gate-complete candidates. `050` and `051` have low corrected completion because E2 rows were reclassified, not because a new deficit was invented.
