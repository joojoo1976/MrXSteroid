## Phase 1 — Technical SEO audit (complete)

Scope: 56 `page.tsx` + 4 `layout.tsx` under `app/`, middleware, configs, public/ files, lib routing map.

### Architecture summary

- Bilingual AR/EN, path-locale routing: `/en/*`, `/ar/*` rewritten (not redirected) by `middleware.ts` to underlying routes. D-01/D-02 priority: Path > Explicit cookie > Saved cookie > Geo-IP > Accept-Language > `'en'`.
- Seven markets (ar-EG, ar-SA, ar-AE, en-US, en-GB, en-CA, en-AU) collapse to `ar`/`en` in `<html lang>` and hreflang.
- Static `public/robots.txt` (allow-all) + static `public/sitemap.xml` (37 bare-path URLs). `public/_redirects` contains a Cloudflare Pages SPA fallback (`/* /index.html 200`) — inert on Vercel.
- `vercel.json`: www→apex 301, security headers. `next.config.ts`: no redirects/rewrites/trailingSlash; `/api/*` headers only.
- Only canonical/hreflang logic in the app: 5 smarttools pages via `generateMetadata` (ar-EG→bare URL, en-US→/en URL). `shared/ui/SEO.tsx` has site-wide canonical/hreflang logic but is **dead code — zero imports, never mounted**.
- Only noindex in the entire app: `app/profile/affiliate/layout.tsx`.
- Global `components/layouts/Footer.tsx` emits `Product` JSON-LD with `aggregateRating 4.9 / 2300 reviews`, `price '79'`, no `url`, no `image` — on every page including `/admin`, `/checkout`.

### Refresh sequence (exact, `app/api/seo/refresh/route.ts`)

1. Auth: CRON_SECRET header XOR admin JWT (profiles.role==='admin' via service-role client); dev bypass `NODE_ENV==='development' && !cronSecret` (L73). Fail-closed in production.
2. Insert run row status:'running' (L100–113).
3. Read last-7-days search logs → frequency map (L117–129).
4. Read pins → pinned ID set (L132–140).
5. Read active seo_keywords (L143–150). Throws on error.
6. Compute per keyword: freshness, seasonal, demand boost (capped +20), legacy+v3 scores, trend status, pinned-protection downgrade, YMYL classification (L159–234).
7. **Write — one update per keyword (L237–255): no transaction, no RPC, no per-update error check; payload includes `last_analyzed_at` (non-existent column).**
8. Snapshot regeneration for 'en'/'ar': re-read, skip if 0 rows (L271), upsert onConflict (year,week_number,language) overwriting snapshot_data (L292–298). No blocklist consulted. No transaction.
9. Finalize run 'completed' (L312–329).
10. Catch: mark 'failed', error_log, 500.

### Run status summary

- DB check: 'running'|'completed'|'failed'. TS type `SeoRefreshRun` (server/seo/types.ts:170) also allows 'partial'|'cancelled' — rejected by DB, never used; no partial-success recording even when only one language snapshot regenerated.
- Run rows write-only; stale 'running' never swept; **run status cannot be trusted as evidence of successful refresh** (defect 1).

### Search log summary

- Logged: raw query ≤100 verbatim, normalized, query_hash SHA-256, language, locale, country_code, results_count, clicked_result ≤255, search_success, session_reference_hash (always null). No IP/UA/cookies. No rate limit (defect 10). No retention. Fallback basic logger on advanced-insert failure (route L39–41 → seoService.ts:302).

### Bottom line on the critical requirement

"A failed refresh must never destroy the last known-good dataset; historical snapshots preserved" — **structurally satisfied but incidentally**: update-only refresh (no delete-then-insert), past-week rows physically separate. However: (a) current-week snapshot mutated in place with no rollback; (b) Tier 2 can overwrite current-week snapshot with empty data that refresh won't repair (defect 9); (c) refresh core score-write path is a **silent no-op due to non-existent `last_analyzed_at`** (defect 1) — 'completed' while persisting nothing.
