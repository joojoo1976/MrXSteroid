# SmartTools Catalog Rows 1–10 — Runtime Path Audit

**Date:** 2026-10-26  
**Scope:** Read-only first-pass trace of the first ten rows in `lib/tools/smartToolsCatalog.ts:41-52`. This establishes catalog-to-page/component/state wiring and identifies evidence gaps. It is not a calculation-validity, clinical-safety, accessibility, live-Supabase, or complete acceptance review. No implementation, test, database, or route was changed for this audit.

## Summary

The catalog's component/engine/schema declarations are not uniformly the active route's computation path. Rows 2–9 resolve through generic slug loaders to legacy wrappers that render `features/calculator` components. Several declared `lib/tools/engines/*` files are not imported by those active UI paths; tests for a declared engine therefore do not establish that the corresponding SmartTools page executes it. Row 1 and row 6 have separate V6 pages that are not consistently the catalog route. Row 10 directly uses its declared engine/schema, but initializes a non-empty drug-simulation scenario and automatically stores local drafts.

The runtime route `/smarttools/body-composition/bodyfat` also renders two headers and two footers (HTTP 200; server HTML count reproduced at local preview port 3101). This is caused by `app/smarttools/layout.tsx:35,41` plus `LegacyPageShell.tsx:28-34` and affects the generic path for rows 2–9. See the header/footer audit in `GENIUS_TOOL_STANDARD_V3.md`.

## Cross-cutting gaps and limits

1. The generic loader plus `LegacyPageShell` duplicates the outer SmartTools chrome for rows 2–9; runtime evidence confirms two header/footer elements on row 2. No broad shell fix was made under the current phase gate.
2. Catalog file-presence checks do not prove the declared engine is used. Rows 1, 2, 6, 8, and 9 show material metadata/runtime divergence; rows 3–5 also use feature hooks instead of a demonstrated catalog engine call path.
3. Tests on standalone V6 engines, helper functions, or feature hooks do not substitute for a test of the published category route and its active component.
4. Several flows include defaults for sex/activity/body composition, drug/compound dose, duration, cycle support, or body-composition scenarios; several persist personal or health-adjacent values to browser storage or Supabase. These are evidence flags, not a complete privacy or medical-safety assessment.
5. This audit did not run row-specific tests, inspect live Supabase/RLS, verify reference sources, execute browser accessibility checks, or assess numerical validity. Those states remain **NOT VERIFIED**.
