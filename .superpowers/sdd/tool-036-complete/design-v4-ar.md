## 2. عقد البيانات (Data Contracts)

العقدة الأساسية: **الوقت مطلق دائمًا** — لا `dayIndex` أسبوعي في أي نموذج تخزين؛ ويُمرَّر الزمن `now` صراحةً إلى كل دالة محرك (لا `Date.now()` داخل المحرك).

```ts
// ====== الأحداث المسجّلة (Ground Truth) ======
type EventSource = 'planned' | 'logged' | 'imported';

interface InjectionEvent {
  id: string;                 // uuid — ثابت عبر التصدير/الاستيراد (مصدر تطابق ال dedupe)
  occurredAt: string;         // ISO-8601 مع إزاحة صريحة (لا وقت بلا منطقة زمنية أبدًا)
  siteId: SiteId;             // متحقق ضد BODY_SITES
  volumeMl: number;           // يُحفظ وقت الحدث (التاريخ لا يتغير إذا غيّر المستخدم التركيز لاحقًا)
  doseMg: number;
  compoundIds: string[];      // مفاتيح ESTER_PROFILES
  painScore?: number;         // صحيح 0..10، ملتصق بالحدث
  note?: string;              // يُطبَّع NFC قبل الحفظ (ثبات الترميز العربي)
  source: EventSource;
  createdAt: string;          // ISO — وقت التسجيل الفعلي
}

// ====== الخطة المقترحة ======
interface PlanSpec {
  compounds: Array<{
    compoundId: string;
    weeklyDoseMg: number;
    concentrationMgMl: number;
    injectionsPerWeek: 1 | 2 | 3 | 4;
  }>;
  preferredSites: SiteId[];    // ترتيب التفضيل — لا يُفرض كتدوير أعمى
  rotationMode: 'least-recently-used' | 'fixed-order';
}

interface Prefs {
  locale: 'ar' | 'en';
  tz: string;                  // IANA — يُلتقط وقت الإنشاء ويُحفظ في occurredAt
  lateToleranceHours: number;  // تفضيل شخصي معلن — ليس قاعدة طبية
  acknowledgedAt?: string;     // ISO — محلي فقط، لا يُصدَّر
}

interface AppState {
  schemaVersion: 2;            // الهجرة إلزامية ومُختبَرة حتى لو بدأت من نظيفة
  events: InjectionEvent[];
  plan: PlanSpec;
  prefs: Prefs;
}

// ====== ظرف التصدير/الاستيراد ======
interface ExportEnvelope {
  format: 'tool-036-export';
  schemaVersion: 2;
  exportedAt: string;          // ISO
  checksum: string;            // sha256 فوق الترميز الكانوني (مفاتيح مرتّبة + NFC)
  payload: { events: InjectionEvent[]; plan: PlanSpec; locale: 'ar' | 'en' };
  // prefs الأخرى وacknowledgedAt محليان — لا يُصدَّران
}

type ImportResult =
  | { ok: true; added: number; skippedDuplicates: number; warnings: string[] }
  | { ok: false; errors: ImportError[] };   // { code, path, messageEn, messageAr }
// أكواد الأخطاء على الأقل: not-json · schema-mismatch (مع path) · wrong-format ·
// version-unsupported · checksum-mismatch · conflict-id (نفس id بمحتوى مختلف → رفض، لا دمج صامت)

// ====== تقرير الانحراف (D4 — بلا مؤشر مركب) ======
interface DriftItem {
  scheduledAt: string;
  status: 'matched' | 'late' | 'missed' | 'extra' | 'site-changed';
  actual?: { occurredAt: string; siteId: SiteId };
  deltaHours?: number;
  reason: string;              // جملة مفسّرة مولَّدة من القواعد المعلنة
  ruleId: string;              // أي قاعدة حكمت هذا السطر (تُفتح في سجل المصادر)
}
interface DriftReport {
  windowStart: string; windowEnd: string;
  computedAt: string;          // "آخر تحديث" — مطلوب صراحةً في D4
  items: DriftItem[];
  summary: { matched: number; late: number; missed: number; extra: number; siteChanged: number };
}

// ====== سجل القواعد الطبية (D2) ======
interface MedicalRule {
  ruleId: string;
  claimEn: string; claimAr: string;
  source: { type: 'label' | 'secondary' | 'consensus' | 'unverified';
            ref: string; confidence: 'High' | 'Moderate' | 'Low' | 'None' };
  applicabilityEn: string; applicabilityAr: string;   // نطاق الاستخدام — إلزامي
  status: 'active' | 'display-unverified' | 'disabled';
}

// ====== ViewModel ======
interface Tool036ViewModel {
  proposal: Proposal;          // من PlanSpec وحدها — بأوقات مطلقة
  actuals: InjectionEvent[];   // من الأحداث وحدها
  drift: DriftReport;
  guard: GuardView;            // كل تحذير يحمل ruleId
  explanations: Record<string, Explanation>;  // كل رقم معروض له سلسلة "لماذا"
}
```

**قواعد عملية ملزمة متسقة من العقود:**
- إنشاء حدث: `createEvent(input, { now, idGen })` — القابلية للإعادة إنتاج كاملة في الاختبارات (لا `crypto.randomUUID` مباشرة داخل المنطق).
- لا قيمة معروضة تُشتق داخل المكوّن — كل شيء من `ViewModel` واحدة تُحسب دفعة واحدة عند كل تعديل (ضمانة D1/S1).
- اصطدام المعرفات عند الاستيراد: `conflict-id` → **رفض الملف** برسالة، لا دمج صامت (حماية المعنى — D3).

## 4. مراجعة القواعد الطبية (D2) — الحالات المُقترحة

| القاعدة | مصدرها في الكود اليوم | الحالة في V4 |
|---|---|---|
| نصف-عمر 7 إسترات | `evidenceId` لكل مركّب + درجة ثقة | **active** — تُعرض مع درجة الثقة |
| مناطق الحجم ≤2 / ≤5 / >5 mL | B01 "commonly cited" / B04 + `limited evidence` صريح | **active مع إعادة تسمية**: "حدود مُدوّنة في المراجع — ليست حدودًا شخصية" + عرض الثقة |
| سقف كل موقع (mL) | `siteCeilingMl` بمصدر | نفس معالجة الحجم |
| نافذة الالتئام 7/14 | معاد استخدامها من سياق `varicella-healing` — لا مصدر عضلي في المستودع | **disabled** — لا استنتاج جاهزية إطلاقًا؛ عرض واقعي فقط: "آخر استخدام: N يومًا" + جملة صريحة "لا تُوجد قاعدة معتمدة تحدد زمن الراحة" |
| راحة الموقع 7 أيام (تحذير 14) | لا مصدر طبي في المستودع | **تفضيل شخصي** في `prefs` (الافتراضي 7) — المخالفات تُعرض كتجاوز لتفضيل المستخدم لا كتحذير طبي، مع تعديل من الواجهة |
| أحجام/قواعد التوصيات الأخرى + إشارات التوقف الحمراء | لا شيء موثّق | **لا تُضفَف كمعيار تشخيصي**؛ تُعرض "راجع مختصًا" تصريحية فقط؛ أي معيار جديد يتطلب مصدرًا موثّقًا في السجل قبل الظهور |
| نطاقات الألم 0-10 | لا مصدر | معلوماتية فقط — بلا استنتاج طبي |

**آلية الإلزام:** اختبار اكتمال في CI — كل ادّعاء صحّي في أي قيمة معروضة يشير إلى `ruleId` موجود في السجل، وكل قاعدة `active` تملك `source.ref` غير فارغ و`applicability`. قاعدة بلا مصدر لا تدخل `active` أبدًا.

## 5. Plan vs Actual — القواعد المعلنة (D4، بلا مؤشر مركب)

قبل أي حساب، تُعلَن القواعد للمستخدم وتُخضع للتعديل:

- **المطابقة:** حدث فعلي يطابق خانة مجدولة إذا وقع ضمن `lateToleranceHours` (تفضيل شخصي، يُعرض قيمته).
- **متأخر (late):** وقع بعد التolerance وقبل نهاية اليوم — مع `deltaHours` وسبب.
- **فائت (missed):** خانة مجدولة بلا حدث فعلي ضمن النافذة — بسبب "لا حدث مطابق".
- **إضافي (extra):** حدث مسجّل بلا خانة مجدولة.
- **تغيير موقع (site-changed):** وقت مطابق بموقع مختلف — يُعرض كـ matched مع سبب صريح.
- **`computedAt`** يظهر في رأس التقرير ("آخر تحديث").

**لا نسبة التزام ولا درجة في هذه المرحلة.** بعد المعاينة والتجربة، يُعرض للمستخدم صيغة أي مؤشر مركب (مثلًا: نسبة المطابقة على نافذة محددة مع عدد الأحداث المُحسوب عليه) للموافقة عليها قبل بنائها — كما اشترط المستخدم.

## 6. الاستيراد والتصدير (D3)

- **التصدير:** `ExportEnvelope` (في §2) — JSON، مفتاح `schemaVersion`، `checksum` فوق ترميز كانوني (مفاتيح مرتّبة + NFC للنصوص العربية).
- **الاستيراد:** تحقق zod مسبق → أكواد أخطاء محددة بمسار الحقل ورسائل ar/en (`not-json`, `schema-mismatch` مع path, `version-unsupported`, `checksum-mismatch`, `conflict-id`) → dedupe بالمعرّف مع تقرير `added/skipped`.
- **الفحص الحاسم:** اختبار `Export → Import → Compare` — تطابق منطقي كامل بعد تطبيع؛ أي فقدان أو تغيير معنى = فشل المرحلة.
- **FHIR:** التصدير فقط في V4، عبر `FhirBundleSchema` المختبَرة فعليًا؛ لا استيراد FHIR؛ لا عبارة "متوافق مع FHIR" في أي واجهة قبل وجود اختبار مخطط — وعند الظهور يُذكر نطاق التوافق بدقة.

## 7. استراتيجية الفرع والمعاينة والاستبدال (D6)

- **الفرع:** `feat/tool-036-v4-core` — كل تطوير فيه؛ `main` والمسار الحيّ V3 لا يمسّان.
- **المعاينة:** كل push للفرع يولّد Vercel Preview (سلوك المشروع الحالي) على **مسار معاينة مستقل** — لا Flag دائم.
- **V3 تبقى كما هي:** ملفاتها واختباراتها (76) وتغطيتها الحية دون تعديل عبر كل المراحل.
- **F8 الاستبدال:** خطوة منفصلة **لا تُجدول ولا تُنفَّذ** قبل: (أ) دليل السيناريوهات الخمسة كاملًا، (ب) موافقة صريحة. عندها فقط: المسار الأساسي ← V4، مسار المعاينة يُزال أو يُحوِّل، ومكوّن V3 يُتقاعد.

## 8. خطة التنفيذ المرحلية ومعايير القبول

### F1 — العقود وسجل القواعد الطبية
- **النطاق:** `contracts.ts` (كل أنواع §2 + zod) · `rules/registry.ts` (بنود §4 بحالاتها) · اختبارات اكتمال السجل. لا واجهة، لا لمس V3.
- **القبول:** (C1.1) round-trip zod لكل عقدة؛ (C1.2) كل ادّعاء صحّي موجود في محرك V3 الحالي (نصف-عمر، حدود حجم، سقوف، نطاقات ألم، نافذة 7/14) يقابل `ruleId` في السجل — اختبار اكتمال يفشل لو نُسيت قاعدة؛ (C1.3) لا قاعدة `active` بلا `source.ref` و`applicability`؛ (C1.4) قاعدة نافذة الالتئام = `disabled`.

### F2 — نواة الحالة والبقاء (الجزء الأول من P0/D1/D5)
- **النطاق:** reducer نقيّ `applyAction` · محول localStorage · `deleteAll()` · إطار هجرة `schemaVersion` (يبدأ من v2 نظيفة لكن الهجرة مُختبَرة باصطناع v1) · منشئ الظرف للتصدير (لا استيراد بعد).
- **القبول:** (C2.1) نقاء reducer (بلا تلوّث، نفس المدخلات → نفس الناتج)؛ (C2.2) **S3 الاستمرارية:** إغلاق/إعادة فتح يستعيد كل شيء (اختبار محاكاة مخزن)؛ (C2.3) `deleteAll` يمحو كل مفاتيح المخزن (اختبار عدّ المفاتيح)؛ (C2.4) صفر شبكة أثناء عمليات الحالة (جاسوس `fetch`/XHR/Beacon)؛ (C2.5) اختبار هجرة v1 اصطناعية → v2.

### F3 — محرك الوقت المطلق والفصل (الجزء الثاني من P0)
- **النطاق:** وحدة محرك V4 الجديدة: `compileProposal` (أوقات مطلقة بمنطقة زمنية معلنة) · `siteRecencyFromEvents` (أيام فعلية حقيقية) · `rotationViolations` عبر الأفق كاملاً · rotator v1 بمنطق LRU · `buildDriftReport` نواة (بلا عرض بعد). استيراد الوظائف الصحيحة من محرك V3 (§9) بتعديل صفر على ملفه.
- **القبول:** (C3.1) نقاء وdeterminism (زمن مُمرَّر، لا `Date.now()` داخلية — اختبار نفس المدخلات في تاريخين مختلفين)؛ (C3.2) اختبار DST صريح (حقن تاريخ حول تغيير ساعة لا يُنتج انزياحًا ولا تكرارًا)؛ (C3.3) `siteRecency` فوق 3 أسابيع تُرجع عدّ صحيح ≥14 يومًا (قابلية الوصول لدرجة `ready` الحقيقية — عكس عيب G5)؛ (C3.4) `rotationViolations` تكشف إساءة استخدام موقع بعد أسبوعين (عكس ضعف التحقق الأسبوعي)؛ (C3.5) اختبارات V3 الـ 76 كلها خضراء + build ناجح (حارس ارتداد).

### F4 — قشرة V4 على مسار المعاينة + الترابط
- **النطاق:** مسار المعاينة (§7) · قشرة V4 جديدة تُستورد منها مكوّنات V3 العامة (التقويم، الرسم البياني) دون تعديلها · تحرير الخطة + تسجيل حدث فعلي + عرض الاقتراح الحيّ.
- **القبول:** (C4.1) **S1 الترابط:** اختبار واحد يغيّر إدخالًا واحدًا (جرعة أو عدد حقن) ويثبت تحديثًا متزامنًا: اقتراح + تقويم + حارس + مخالفات + mg/wk — بلا أي قيمة قديمة (assert على كلها معًا)؛ (C4.2) `git diff` على ملفات V3 = فارغ؛ (C4.3) حزمة مسار المعاينة <150 kB + build + 310/310.

### F5 — Plan vs Actual (الابتكار الأول)
- **النطاق:** عرض `DriftReport` كاملًا (جدول فروقات + حالات + أسباب + `ruleId` + قواعد tolerance المعلنة + `computedAt`) — **بلا مؤشر مركب** · تسجيل حدث فعلي من الواجهة.
- **القبول:** (C5.1) **S2 الانحراف:** تسجيل حدث فعلي → التقرير يتحدث: سطر جديد بسبب مفسّر وقاعدة معلنة؛ (C5.2) خانة بلا حدث بعد تجاوز tolerance تظهر `missed` بسبب صحيح؛ (C5.3) كل سطر يفتح مصدر حكمه؛ (C5.4) غياب تام لأي رقم مركب 0-100 أو نسبة (assert نصي).

### F6 — الاستيراد والتصدير
- **النطاق:** تصدير JSON بالظرف · استيراد بالتحقق والأكواد · دمج بالمعرّف مع تقرير · تصدير FHIR عبر `FhirBundleSchema` (لا استيراد FHIR).
- **القبول:** (C6.1) **S4 دورة البيانات:** Export → Import → Compare تطابق منطقي كامل (اختبار مسجّلات متنوعة: أحداث عربية مُرمّزة، ألم، ملاحظات، مركّبات متعددة)؛ (C6.2) كل ملف تالف/غير مطابق/إصدار قديم/تعارض معرّف يُرفض برسالة محددة (اختبار لكل كود خطأ)؛ (C6.3) حزمة FHIR تمر `FhirBundleSchema` (لا ادعاء توافق بلا اختبار)؛ (C6.4) أي فقدان بيانات في الدورة = فشل المرحلة.

### F7 — الإقرار والخصوصية وإشارات التوقف + بوابة الاستبدال
- **النطاق:** شاشة الإقرار عند أول استخدام (نصها: ليست للتشخيص ولا وصف جرعات؛ الحسابات ليست تصريحًا طبيًا؛ متى تحتاج تقييمًا طبيًا) · واجهة حذف كامل · تطبيق سياسة التحذيرات (كل تحذير معروض من السجل) · إخلاء مسؤولية فعلي.
- **القبول:** (C7.1) **S5 الموثوقية والخصوصية:** نتائج المحرك determinism صادقة + مصادر التوصيات معروضة (اختبارات F1+F3)؛ (C7.2) صفر طلبات شبكة أثناء سيناريو استخدام كامل (جاسوس شبكة)؛ (C7.3) الإقرار بوابة دخول + يُخزَّن ولا يُصدَّر؛ (C7.4) الحذف الكامل موثّق (عدّ المفاتيح بعد = 0)؛ (C7.5) **وثيقة دليل السيناريوهات الخمسة كاملة** تُسلَّم للمستخدم.

### F8 — الاستبدال (لا تُجدول تلقائيًا)
- **الم前置:** موافقة صريحة على الوثيقة بعد استلام دليل F7. عندها فقط: نقل المسار الأساسي ← V4، تقاعد مكوّن V3، تحديث العقود، إزالة/تحويل مسار المعاينة.

**تتابع منطقي (لا يُختصر):** F1 → F2 → F3 (P0 كامل) → F4 → F5 → F6 → F7 → باب موافقة → F8.
