## 1. حكم تشخيصي عام

V3 نجحت كـ**إعادة بناء واجهة** وفشلت كـ**منظومة**: المحرك غني (24 دالة نقية موثّقة)، لكن الواجهة لا تغذّيه بالحقيقة ولا تعرض ناتجه كاملًا. النتيجة: لوحة أجمل تعمل على بيانات افتراضية دائرية — الخطة تُشتق منها البيانات ثم تُختبر بنفسها.

**الأربعة انتقادات التي طرحتها — أؤكدها بالدليل:**

| انتقادك | الدليل في الكود |
|---|---|
| 1. لا حفظ ولا استعادة | لا يوجد `localStorage` في المكوّن إطلاقًا؛ `scores`, `shotDays`, `compoundId`… كلها `useState` تُفقد عند إعادة التحميل |
| 2. خطة 12 أسبوعًا غير معروضة + حالة الموقع من الخطة لا من سجل فعلي | السطر 187: `ganttRows(rotationPlan).filter((r) => r.weekIndex === 0)` — **11 أسبوعًا محسوبة ومهمشة**. والسطر 188: `validateRotation(logs, …)` حيث `logs` مأخوذة من الخطة نفسها (السطر 186-189) — تحقق دائري |
| 3. تغيير الموقع لا يعيد بناء الجدول | `selectedSite` تؤثر فقط في badge/comfort؛ مواقع الجدول مشتقة `DEFAULT_ROTATION_SITES[i]` مستقلة عن الموقع المختار — أربعة إدخالات لا تؤثر إلا في بطاقة واحدة |
| 4. التصدير حلول أساسية | `window.print()` فقط، بينما `buildFhirBundle` موجود في المحرك **ولا يُستورد** في الواجهة (نتيجة grep: 0 استخدام) |

**فجوات جذرية إضافية وجدتها بالقراءة:**

- **G5 — مقياس الألوان ميّت:** `siteRecency` تُحسب من سجل هذا الأسبوع فقط → `daysSince ≤ 6` دائمًا → درجة `ready` (≥14 يوم) **لا تظهر أبدًا**. أربع درجات معلنة، اثنتان قابلتان للوصول.
- **G6 — التدوير ثابت غير متسق:** `buildRotationPlan` تفترض `for (const day of [0, 4])` (حقنان/أسبوع) بينما الواجهة تسمح 1-4 → مع 3 أو 4 حقن يُتجاهَل 33%-50% من الجدول، والمؤشر `logs.length % sites.length` تدوير أعمى لا يراعي آخر استخدام.
- **G7 — المساعد ليس مساعدًا:** `advisories` نصوص ثابتة من `assessComfort` — لا يشرح لماذا، ولا يرصد نقص بيانات، ولا يربط بالخطة، ولا يذكر تعارضًا.
- **G8 — `?? 7` يخفي غياب البيانات:** `healingStatus(recency[selectedSite] ?? 7, …)` يعرض "نافذة الالتئام" حتى لو لم يُستخدم الموقع إطلاقًا.

## 2. الفارق: ما تفعله V3 فعلًا مقابل المنظومة المتقدمة

| البُعد | V3 اليوم | المنظومة المطلوبة |
|---|---|---|
| مصدر الحقيقة | الخطة المقترحة نفسها (دائرية) | سجل استخدام فعلي مستقل + خطة مقترحة فوقه |
| المدخلات | منفصلة، جزء يتأثر | نواة واحدة، كل تغيير يعيد بناء كل الناتج |
| الزمن | أسبوع واحد (dayIndex 0-6) | تواريخ مطلقة، أفق كامل قابل للتوسعة |
| التحقق | من الخطة بالخطة، أسبوع واحد | من السجل الفعلي عبر الأفق كاملًا |
| المساعد | نصوص ثافية | طبقة تفسير تُولَّد من المحرك مع سلسلة الحساب |
| البقاء | لا شيء | استعادة + هجرة مخطّطة + نسخ احتياطي |
| التصدير | طباعة المتصفح | بيانات مهيكلة قابلة للاستيراد (round-trip) |
| الموثوقية الطبية | مصادر مذكورة لكن قواعد مُعاد استخدامها | كل قارة تحمل مصدرها ونطاق تطبيقها ودرجة ثقتها |

## 3. تصور V4 — المبادئ الخمسة

1. **نواة واحدة:** `State → Engine → ViewModel`. لا حساب في الواجهة. كل عرض مشتق من نواة واحدة محسوبة دفعة واحدة (reducer).
2. **فصل المقترح عن المسجّل:** `Plan` (ما أخطط له) ≠ `Events` (ما فعلته فعلًا). كل ميزة تصرّح بأيّ من الاثنين تعتمد عليه.
3. **زمن مطلق:** كل حدث بتاريخ حقيقي. `dayIndex` يصبح تفصيلة عرض لا نموذج تخزين.
4. **المساعد تفسير لا واجهة:** كل رقم معروض له زر "لماذا؟" يعيد سلسلة الحساب من المحرك نفسها.
5. **Determinism:** المحرك نقي (لا `Date.now()` داخله)، الزمن يُمرَّر إليه. الواجهة وحدها تملّك الساعة.

## 4. نموذج البيانات الجديد (القرار الأهم)

```ts
interface InjectionEvent {
  id: string;
  occurredAt: string;          // ISO مطلق — أساس كل الحسابات الجديدة
  siteId: string;
  volumeMl: number;
  doseMg: number;
  compoundIds: string[];

interface AppState {
  schemaVersion: number;       // الهجرة إلزامية
  events: InjectionEvent[];
```

## 5. عرض المقترحات (مشكلة / تغيير / قيمة / معيار قبول)

### P1 — نواة محرّك متفاعل واحدة
- **الحالة:** موجود جزئيًا (المحرك نقي) / ناقص الوصل (تجميع في الواجهة).
- **المشكلة:** أربعة إدخالات لا تؤثر إلا في بطاقة واحدة؛ لا يوجد إشعار "أُعيد بناء كل شيء".
- **التغيير:** reducer واحد: أي تعديل في `AppState` → إعادة حساب كاملة → كل البطاقات محدَّثة دفعة واحدة.
- **القيمة:** الأداة تصبح "منظومة" لا "مجموعة بطاقات".
- **معيار القبول:** تغيير الموقع أو الجرعة في اختبار واحد يُحدّث: التقويم + التدوير + الجانت + الحارس + المساعد في عملية واحدة، بلا قيمة قديمة متبقية (assert على المخرجات كلها معاً).

### P2 — سجل مستمر حقيقي (Plan ≠ Actual)
- **الحالة:** غير موجود.
- **المشكلة:** إعادة التحميل تمحو كل شيء؛ لا يمكن تسجيل "حقنت فعلًا" ولا مقارنته بالخطة.
- **التغيير:** طبقة أحداث مطلقة + استعادة من `localStorage` + نافذة "سجل هذا الأسبوع" (خطة/فعلي/تجاوز).
- **القيمة:** الأداة تتذكّر المستخدم وتصبح مفيدة يوميًا لا لحظيًا.
- **معيار القبول:** إغلاق المتصفح → إعادة الفتح → استعادة كاملة مع اختبار هجرة `schemaVersion v1→v2`؛ بعد تسجيل 3 أحداث فعلية تُبنى الخريطة والتدوير عليها وحدها.

### P3 — خطة الأفق الكامل (12 أسبوعًا) قابلة للتحديث والتحقق
- **الحالة:** موجود جزئيًا (محسوبة ومهمشة — السطر 187).
- **المشكلة:** 11 أسبوعًا مهملة؛ التحقق من أسبوع واحد.
- **التغيير:** جدول أفق قابل للتوسعة + فحص مخالفات عبر الأفق كله + إعادة حساب الخطة عند تغيّر السجل.
- **القيمة:** رؤية كاملة + اكتشاف مبكر لتعارضات الاستخدام المتكرر.
- **معيار القبول:** إظهار 12 أسبوعًا؛ `validateRotation` على أفق ممتد يكتشف إساءة استخدام موقع بعد 3 أسابيع (اختبار صريح).

### P4 — محرك تدوير قيد-موجّه (إصلاح G6)
- **الحالة:** موجود لكنه أعمى (`logs.length % sites.length` + `[0,4]` مطبّعة).
- **المشكلة:** يتجاهل آخر استخدام الفعلي، ويُفترض حقنان أسبوعيًا بغضّ النظر عن الإعداد (1-4).
- **التغيير:** خوارزمية: أقل-استخدام-حاليًا + تبديل جهات (L/R) + راحة دنيا لكل منطقة (من `prefs`)، مع مراعاة عدد الحقن الفعلي.
- **القيمة:** تدوير يعكس الواقع والنية، ويُبقي على وعد "L glute → R glute → Ventro" فعليًا.
- **معيار القبول:** خصائص (property tests): لا يُعاد موقع قبل راحته الدنيا؛ لا يتعادل L/R متتاليان بلا سبب؛ يخدم 1-4 حقن/أسبوع بشكل صحيح.

### P5 — المساعد كطبقة تفسير فوق المحرك (إصلاح G7)
- **الحالة:** غير موجود (نصوص ثافية).
- **المشكلة:** لا يشرح "لماذا"، لا يرصد نقص بيانات، لا يذكر تعارضًا.
- **التغيير:** منظومة تفسير مولَّدة من ناتج المحرك: تلخيص نشاط الأسبوع + تعارضات + نقص بيانات + مبرّر كل تنبيه بمعرّف دليل.
- **القيمة:** الثقة بالنتيجة بدل قبولها عمياء.
- **معيار القبول:** كل رقم معروض له قناة "لماذا؟" تعيد سلسلة حساب صحيحة؛ كل تعارض يُذكر مع سببه وموقته؛ نقص البيانات يُعلن صراحة بدل التمويه (`?? 7` يُزال).

### P6 — تصدير/استيراد مهيكل (إصلاح G4-التصدير)
- **الحالة:** موجود جزئيًا (`buildFhirBundle` مبني في المحرك، غير موصول).
- **التغيير:** تصدير JSON/CSV لسجل الأحداث + حزمة FHIR + استيراد round-trip.
- **القيمة:** نسخ احتياطي حقيقي + قابلية للنقل بين الأجهزة + استعداد لتكاملات.
- **معيار القبول:** تصدير → استيراد → تطابق كامل بلا فقدان؛ الحزمة تمر عبر `FhirBundleSchema`.

### P7 — تذكيرات وأوقات (`ics` + منطقة زمنية)
- **الحالة:** غير موجود. العدّاد يعمل لكن لا يُنبّه.
- **التغيير:** ملف `.ics` بـ `RRULE` للخطة + دعم مناطق زمنية وDST صريح.
- **القيمة:** الالتزام الفعلي بالخطة — الجذر الأهم للفائدة.
- **معيار القبول:** اختبار DST (تغيير ساعة) لا يُحدث حقنًا مكررًا أو مفقودًا؛ الملف يفتح في تقويم قياسي.

### P8 — تحليلات الامتثال والحمل
- **الحالة:** غير موجود.
- **التغيير:** نسبة التزام فعلية/مقترحة، توزيع الحمل لكل موقع، اتجاه الألم (متوسط 5 متحرك على سجل فعلي).
- **القيمة:** رؤية الاتجاه لا اللقطة.
- **معيار القبول:** كل تحليلة معرّفة بصيغة معروضة ومحسوبة من الأحداث الفعلية فقط.

### P9 — عدم الاتصال + خصوصية البيانات الصحية
- **الحالة:** موجود ضمنيًا (لا شبكة أصلًا) — يجب تثبيته كسياسة.
- **التغيير:** لا حسابات، لا مزامنة سحابية، تصدير صريح فقط، حذف كامل بزر واحد، سياسة تخزين موثّقة.
- **القيمة:** بيانات صحية لا تغادر الجهاز — شرط ثقة أساسي.
- **معيار القبول:** لا طلبات شبكة أثناء التشغيل (اختبار)؛ حذف كامل موثّق.

### P10 — تعدد المركّبات المتراكمة
- **الحالة:** موجود ناقص (المحرك يدعم `compounds[]`، الواجهة سلّة واحدة).
- **التغيير:** إضافة/حذف مركّبات مع جمع mg/wk وحجم أسبوعي مشترك ومنحنى تراكم مركّب.
- **القيمة:** انعكاس حقيقي لبروتوكولات متعددة المركّبات.
- **معيار القبول:** مركّبان → mg/wk والحجم الأسبوعي والتراكم المركّب صحيحة حسابيًا (اختبارات صريحة).

## 6. الابتكارات المميزة (مع معيار قبول ومعيار فشل)

| الابتكار | الفكرة | معيار القبول | معيار الفشل (Kill criterion) |
|---|---|---|---|
| **مقياس الانحراف (Plan-vs-Actual)** | رقم 0-100 يقيس كم ابتعد السجل عن الخطة + تفسير المكوّن الرئيسي للانحراف | بعد أسبوعين من الأحداث المتسقة، يتذبذب بين 90-100؛ يهبط >15 نقطة عند تجاوزين متتاليين | إن بقي الانحراف معروفًا بالعين دون رقم → فاشل |
| **إعادة التدوير الذكية (P4)** | constraint solver بدل round-robin | property tests تُثبت الراحة الدنيا والتبديل؛ المخرجات أفضل من round-robin في 5 سيناريوهات مرجعية | إن تعطّل عند 4 حقن/أسبوع → فاشل |
| **تلميح تنبؤي مبكر** | "بنفس الالتزام الحالي، تتجاوز راحة deltoid-l في 18 يومًا" — انبثاق من نفس نموذج التراكم | كل تلميح يحدد موقعه ووقته ويتحدث تلقائيًا بعد تغيير الخطة | إن لم يتحدث بعد تغيير الخطة → فاشل |

## 7. موثوقية التوصيات الصحية ومصادرها

**تقييم القواعد الحالية في الكود:**

| القاعدة | الوضع | الحكم |
|---|---|---|
| نصف-عمر الإسترات (7 مركّبات) | لكل منها `evidenceId` + درجة ثقة (High/Moderate/Low) | **جيد** — النموذج المرجعي للحفاظ عليه |
| سقف الحجم 2/5 mL | `limited evidence` مذكور صراحة | مقبول مع بقاء التنبيه بدرجة الثقة |
| نافذة الالتئام 7/14 | معاد استخدامها من سياق `varicella-healing` | **ضعيفة هنا** — يجب إما إعادة مصدرتها لمصدر حقن عضلي، أو تسميتها "إرشاد عام غير ملزم"، أو حذفها |
| `?? 7` fallback | يخفي غياب البيانات | **يجب إزالته** — "لا بيانات" شرعية وأصدق |

**سياسة V4 المقترحة (إلزامية لكل قاعدة صحية):**
- كل قاعدة = `{ ادّعاء، معرّف مصدر، نوع المصدر: label|secondary|consensus|expert، درجة ثقة، نطاق تطبيق }` — تُعرض مع النتيجة لا مخبّأة في التعليقات.
- **لا قاعدة عامة تُقدَّم كخاصة بالمستخدم:** سقف الموقع والراحة الدنيا إرشادات مُدوّنة، وليست وصفة لكل شخص — الواجهة تصرّح بذلك عند العرض.
- **الأداة لا تصف جرعات ولا تتشخّص:** تُخطط حول جرعة يُدخلها المستخدم فقط؛ أي نص يشبه التوصية العلاجية يُرفض تصميمًا.
- **إشارات التوقف الحمراء** (ألم شديد، حمى، احمرار ممتد): توقف مساعد الراحة وتُصرّح "راجع طبيبك" — بقاعدة موثّقة ومصانة باختبار.
- **حدود التخصيص تُصرّح لا تُفترض:** الواجهة تعلن أن الخطة لا تراعي الحمل/أمراض/أدوية/عمر، وأنها ليست بديلاً عن استشارة.
- **إقرار صريح عند أول استخدام** (acknowledgement) يُخزَّن مع الإعدادات.
- مصدر نهائي لكل ادّعاء يُعرض كرابط/معرّف، ومراجعة دورية: أي قاعدة بلا مصدر فعّال تُسحب.

## 8. كيف نثبت أن V4 نقلة نوعية (لا اسمًا أكبر)

**سيناريوهات القبول الكبرى (Scenario Tests):**
- **S1 الانحراف:** المستخدم يتجاوز حقنًا ويسجّل فعلًا متأخرًا → الخطة تُعاد + رسالة انحراف مفسّرة (لا مجرد رقم).
- **S2 الترابط:** تغيير الجرعة أو الموقع → كل المخرجات المعلنة تتحدث في عملية واحدة (اختبار الترابط).
- **S3 البقاء:** إغلاق وإعادة فتح → استعادة كاملة + هجرة schema.
- **S4 الدورة الكاملة:** تصدير → استيراد على جهاز نظيف → تطابق كامل.

**مقاييس كمية:** عدد المخرجات المعروضة المشتقّة من سجل فعلي (0 اليوم → >0 بعد V4) · نسبة القيم المعروضة مع مبرّر ومصدر · اختبارات صادقة · الحزمة <150 kB.

**معيار الفشل الصريح:** إن بقيت الخريطة أو التدوير أو الاحترام تعتمد على الخطة المقترحة بدل السجل الفعلي بعد V4 — فالنقلة لم تحدث مهما كان عدد الوظائف.

## 9. نطاق غير مضمّن + مخاطر

**غير مضمّن:** مزامنة سحابية/حسابات · اقتراح جرعات · تطبيق جوال · تكامل FHIR مباشر مع مزوّد (التصدير ملف فقط أولًا).

**المخاطر وهروبها:** تضخم النطاق (تنفيذ P0/P1 قبل أي ابتكار) · تعقيد solver التدوير (property tests من اليوم الأول) · DST/المنطقة الزمنية (توقيتات صريحة في المحرك) · بيانات صحية محلية (P9 كسياسة لا ميزة) · هجرة البيانات (schemaVersion إلزامي من اليوم).

## 10. الأولويات المقترحة (بانتظار اعتمادك)

- **الأساس (P0):** نموذج الأحداث المطلقة + البقاء + فصل Plan/Actual (P1+P2) — بدونها كل ما دونها زينة منظمة.
- **الترتيب 1:** P3 (الأفق) + P4 (التدوير الذكي) + P5 (المساعد) — القلب.
- **الترتيب 2:** P6 (تصدير/استيراد) + P10 (تعدد المركّبات) + P8 (تحليلات).
- **الترتيب 3:** الابتكارات (مقياس الانحراف، التلميح التنبؤي) + P7 (تذكيرات).
- **P9** سياسة مستمرة طوال التنفيذ.

## 11. قرارات مطلوبة منك قبل أي خطوة

1. هل يُعتمد نموذج الأحداث المطلقة + البقاء + فصل Plan/Actual كـ**P0 إلزامي** (بما يعني كسر توافق النموذج الحالي بدل طبقته فوقه)؟
